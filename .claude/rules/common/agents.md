# 智能体编排

## 可用智能体

### 核心开发智能体

| 代理 | 用途 | 使用时机 |
|-------|---------|-------------|
| planner | 实现规划 | 复杂功能、重构 |
| architect | 系统设计 | 架构决策 |
| tdd-guide | 测试驱动开发 | 新功能、错误修复 |
| code-reviewer | 代码审查 | 编写代码后 |
| security-reviewer | 安全分析 | 提交前 |
| build-error-resolver | 修复构建错误 | 构建失败时 |
| e2e-runner | 端到端测试 | 关键用户流程 |
| refactor-cleaner | 清理死代码 | 代码维护 |
| doc-updater | 文档 | 更新文档 |

### 专项分析智能体

| 代理 | 用途 | 适用场景 |
|-------|---------|----------|
| code-explorer | 深度分析现有代码库功能，追踪执行路径、映射架构层 | 需求开发第二阶段（代码库探索）、理解陌生代码 |
| code-architect | 分析现有模式 → 设计完整功能架构 → 提供可操作实现蓝图 | 需求开发第四阶段（架构设计） |
| code-simplifier | 简化并优化代码，提高清晰度和可维护性 | 重构、质量审查 |
| silent-failure-hunter | 审查静默失败、吞没错误、不良回退 | 质量审查、安全审查 |

### 代码审查者（Code Reviewer）置信度评分

审查发现的问题按置信度评分：

| 分数 | 含义 | 处理方式 |
|------|------|----------|
| 0-25 | 不确定 / 可能是误报 | 忽略 |
| 50 | 真实问题但影响较小 | 记录，不阻塞 |
| 75 | 高度自信，实际会遇到 | 必须关注 |
| 100 | 绝对确定，频繁触发 | 必须修复 |

**仅报告置信度 ≥ 80 的问题**，聚焦真正重要的事项。

## P0 强制智能体使用（不可跳过）

以下场景**必须**使用对应智能体，无需用户提示：

| 场景 | 必须调用的智能体 | 触发时机 |
|------|-----------------|---------|
| 复杂功能/重构 | **planner** | 开始编码前 |
| 架构决策 | **architect** | 设计方案时 |
| 错误修复/新功能 | **tdd-guide** | 实现前先写测试 |
| 刚写完代码 | **code-reviewer** | 编码完成后立即执行 |
| 安全敏感操作 | **security-reviewer** | 提交前 |
| 构建失败 | **build-error-resolver** | 构建报错时立即执行 |
| 理解陌生代码 | **code-explorer** | 首次接触模块时 |
| 死代码清理 | **refactor-cleaner** | 代码维护时 |
| 静默失败审查 | **silent-failure-hunter** | 质量审查时 |

**违反示例（本轮对话的错误）：**
```
修改了 download.service.ts 170+ 行 → 没有调 code-reviewer ❌
做了架构决策（分支检测移执行时）→ 没有调 architect ❌
修复了 404 bug → 没有调 tdd-guide ❌
开发工作流7个阶段全部跳过 → 没有按 development-workflow.md 执行 ❌
```

**验证方式：** 在做上述任何操作前，先问自己"现在这个场景对应哪个智能体？"

## 并行任务执行

对于独立操作，**始终**使用并行任务执行：

```markdown
# 良好：并行执行
同时启动 3 个智能体：
1. 智能体 1：认证模块的安全分析
2. 智能体 2：缓存系统的性能审查
3. 智能体 3：工具类的类型检查

# 不良：不必要的顺序执行
先智能体 1，然后智能体 2，最后智能体 3

```

## 多视角分析

对于复杂问题，使用拆分角色的子智能体：

* 事实审查员
* 高级工程师
* 安全专家
* 一致性审查员
* 冗余检查器
