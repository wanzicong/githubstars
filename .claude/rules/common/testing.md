# 测试要求

## 最低测试覆盖率：80%

测试类型（全部需要）：

1. **单元测试** - 单个函数、工具、组件
2. **集成测试** - API 端点、数据库操作
3. **端到端测试** - 关键用户流程（根据语言选择框架）

## 测试层级（变更验证必须依次通过）

所有变更必须依次通过以下测试：

1. **单元测试** — 验证独立模块功能正确
2. **冒烟测试** — 验证核心流程可用，关键路径无断裂
3. **业务逻辑测试** — 验证业务规则正确、边界情况覆盖

## 测试驱动开发

强制工作流程：

1. 先写测试 (失败)
2. 运行测试 - 它应该失败
3. 编写最小实现 (成功)
4. 运行测试 - 它应该通过
5. 重构 (改进)
6. 验证覆盖率 (80%+)

## 浏览器端测试

* 若项目配置了浏览器类 MCP（如 Playwright），**必须**通过 MCP 在真实浏览器中执行业务逻辑测试
* 不得仅依赖命令行或模拟环境验证前端功能

## 数据库验证

* 涉及数据库的变更，必须验证数据写入、读取、更新、删除操作的正确性

## 测试失败排查

1. 使用 **tdd-guide** 代理
2. 检查测试隔离性
3. 验证模拟是否正确
4. 修复实现，而不是测试（除非测试有误）

## 与其他规则的集成

此规则与以下规则配合：

- [code-review.md](code-review.md) - 测试覆盖率审查
- [coding-style.md](coding-style.md) - 变更验证闭环
- [performance.md](performance.md) - 性能测试基准

## 代理支持

* **tdd-guide** - 主动用于新功能，强制执行测试优先
* **e2e-runner** - 端到端测试专家，使用 Playwright 进行浏览器端验证
