# 依赖管理与调用链追踪

> 本文档整合了 CLAUDE.md 中的依赖关系管理（十）和工具使用规范（八）中的调用链追踪与上下文广度要求。

## 依赖关系管理

执行任何指令前，**必须**充分思考该指令的全部依赖关系：
- 识别直接依赖和间接依赖
- 评估变更的影响范围和潜在风险
- 理清依赖链后再行动，避免遗漏导致的问题

## 调用链追踪（理解逻辑的硬要求）

分析任何业务逻辑时，**禁止只看当前方法或当前文件**。必须追踪完整调用链路。

### 追踪规则

1. **正向追踪** — 从入口点出发，逐层追踪方法调用，直至数据写入/返回的终点
2. **反向追踪** — 从当前方法向上追溯调用方，理清触发来源和上下文
3. **深度要求** — 调用链必须追踪至**链路终点**（数据持久化 / 网络响应 / 消息投递），不得在中途截断
4. **跨层记录** — 每层记录：方法签名、所在文件:行号、输入参数、返回值/副作用

### 输出格式

```
入口: Controller.foo()  [FooController.java:42]
  └─ Service.bar()     [BarService.java:88]
       └─ Mapper.baz()  [BazMapper.java:15]  → SQL: SELECT ...
            └─ DB 写入   [baz 表]
```

**目的**：只有看到完整链路，才能真正理解需求的内在逻辑，避免"改了 A 方法却不知道会影响 C 表"的盲区。

## 上下文广度

除调用链外，变更前还必须收集：

- 相关配置文件（`application.yml`、`.env`、数据库连接配置等）
- 依赖服务状态（MySQL/Redis/MQ 是否运行、端口号）
- 最近 30 天内修改过的相关文件（定位潜在冲突）
- 历史类似变更记录（Git log 中同文件/同功能的提交）

## 变更范围风险矩阵

| 变更文件数 | 风险等级 | 必须执行 |
|-----------|---------|----------|
| 1-2 个文件 | 低 | 反向感知 + 正向感知 |
| 3-5 个文件 | 中 | 完整三步感知法（正向+反向+横向） |
| 6+ 个文件 | 高 | 完整三步感知 + 调用链追踪 + 历史变更审查 |
