# Star 仓库列表页 · 搜索筛选区重设计方案

> 日期：2026-07-31
> 范围：`packages/frontend/src/pages/StarList` 的筛选区（`StarFilterBar` + `StarTimeFilter` + `StarActionBar`）
> 配套原型图：`docs/原型图-Star列表筛选区.html`（浏览器打开即可查看）

---

## 一、现状梳理

当前筛选区在 [index.tsx:427](../packages/frontend/src/pages/StarList/index.tsx#L427) 的一个 Card 内垂直堆叠三层：

| 层 | 组件 | 内容 |
|---|---|---|
| 第 1 层 | `StarFilterBar` | 搜索框 / 语言多选 / 分类树选 / 排序字段 / 排序方向（5 个控件一行） |
| 第 2 层 | `StarActionBar` | 筛选摘要 Tag + 清除按钮 + 批量克隆/下载 + 导出 MD/链接（5 个按钮一行） |
| 第 3 层 | `StarTimeFilter` | 折叠面板：快捷预设 Segmented + 时间字段 + 起止日期 |

## 二、问题诊断（体验 & 布局）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| 1 | **操作按钮夹在两个筛选层中间**，"筛选条件"和"批量操作"两类不同心智的元素交错排列 | index.tsx:438-453 | 视线动线断裂，用户扫读时要在操作按钮中"跳过"才能看到时间筛选 |
| 2 | **冗余 UI**：筛选摘要 Tag 行有一个 link 样式"清除全部"，下方按钮行又有一个实体"清除"按钮，功能重复 | StarActionBar.tsx:63, 74 | 视觉噪音；无筛选时按钮行出现突兀的左边距 |
| 3 | **排序被拆成两个 Select**（字段 + 方向），占 2 个栅格、需 2 次点击 | StarFilterBar.tsx:117-134 | 高频操作路径过长 |
| 4 | **时间筛选的快捷预设被折叠隐藏**，展开后还分"快捷选择/自定义范围"两段、需先选字段才能选日期 | StarTimeFilter.tsx:104-183 | 最高频的"最近 30 天 Star 的仓库"要点 2 次才能触达 |
| 5 | **分类筛选不出现在摘要 Tag 中**（`hasActiveFilters` 含 categoryId，但 Tag 只渲染关键词/语言/时间） | StarActionBar.tsx:48-62 | 从分类页跳转来时用户看不到自己正被分类过滤，容易困惑"列表怎么变少了" |
| 6 | **导出主按钮错位**："导出链接"是 primary 实心按钮，但它实际上是低频操作 | StarActionBar.tsx:97 | 视觉重心错误，首屏最显眼的按钮是个导出 |
| 7 | 5 个控件等分一行，搜索框（最宽需求）和排序方向（最窄需求）同宽 | StarFilterBar.tsx:79-134 | 搜索框 placeholder 都显示不全 |
| 8 | 筛选区整高约 **250~330px**（含摘要和折叠面板），瀑布流首屏被压缩 | — | 列表内容一屏可见条目变少 |

## 三、设计目标

1. **视觉降噪**：筛选区默认高度压缩到约 150px 以内（标题行 + 主行 + 工具行）。
2. **心智分层**：第一行回答"找什么"，第二行回答"怎么排/怎么看/做什么"。
3. **高频前置**：搜索、语言、时间预设一步可达；排序合并为单次选择。
4. **低频收纳**：自定义日期、分类树、清除收进"更多筛选"抽屉/展开区。
5. **状态外显**：已激活筛选统一用可关闭 Tag 呈现（含分类），不藏在折叠面板里。

## 四、推荐方案：主筛选行 + 快捷预设 + 工具行

### 4.1 整体结构（三层 → 两层）

```
┌─ 标题行 ─────────────────────────────────────────────┐
│  Star 仓库列表                    [网格|列表] 切换     │  （保持现状）
├─ 筛选卡 ─────────────────────────────────────────────┤
│  ① 主行   [🔍 搜索 弹性宽] [时间预设▼] [语言▼] [排序▼] │
│           [⚙ 更多筛选(2)]                             │
│  ② 摘要行  当前筛选：[关键词×][语言×][时间×][分类×] 清除全部│  ← 仅在有筛选时出现
├─ 工具行（独立，不再夹中间）────────────────────────────┤
│  ③ 已选 n 项 [批量克隆] [批量下载] │ [导出MD] [导出链接] │  ← 仅在有选中时出现
└──────────────────────────────────────────────────────┘
```

### 4.2 主行五个槽位

| 槽位 | 组件 | 说明 |
|---|---|---|
| 搜索框 | `Input.Search` | `flex: 1`，最小 220px，占据剩余宽度（修复问题 7） |
| 时间预设 | `Select` 或 `Dropdown` | 固定宽 130px：不限/今天/7天内/30天内/90天内/半年内/一年内/自定义…。选"自定义…"展开更多筛选并聚焦日期。预设作用于 `dateField`（默认 starred_at） |
| 语言 | `Select multiple` | 固定宽 160px，`maxTagCount={1}`，沿用现有 options |
| 排序 | **单个 Select 合并选项** | 固定宽 150px：`Star 最多 / Star 最少 / 最近 Star / 最早 Star / 最近更新 / 最近推送 / Fork 最多 / 仓库最大 / 创建最新`，值编码为 `字段:方向`，选中后拆成 `sortBy`/`sortOrder` 两个 URL 参数（修复问题 3，向后兼容旧 URL） |
| 更多筛选 | `Button` + Badge |  Badge 显示"高级条件激活数"（自定义日期、分类）。点击展开第二层面板 |

### 4.3 更多筛选展开区（默认收起）

```
┌ 更多筛选 ─────────────────────────────────┐
│  时间字段  [Star 时间▼]   自定义 [起] ~ [止]  │
│  仓库分类  [树选▼]                          │
│                              [重置] [收起 ▲] │
└────────────────────────────────────────────┘
```

- 时间字段 + 自定义日期从 `StarTimeFilter` 平移过来，**不再要求先选字段**：选了日期而没选字段时自动落 `starred_at`（修复问题 4 的交互卡点）。
- 分类 TreeSelect 移入此处，激活后出现在摘要行（修复问题 5）。

### 4.4 摘要行与工具行

- **摘要行**：仅 `hasActiveFilters` 时渲染；Tag 覆盖 关键词/语言/时间/分类 四类 + 末尾一个"清除全部"文字按钮（删除按钮行里重复的"清除"，修复问题 2）。
- **工具行**：仅 `selectedCount > 0` 时出现，文案 `已选 n 项`；克隆/下载为主操作，导出 MD/导出链接降级为普通按钮并右对齐（修复问题 1、6）。

### 4.5 交互细节

- 排序 Select 选中即生效（onChange 写 URL），保留 `sortBy`/`sortOrder` 双参数格式，旧书签不破坏。
- 时间预设直接平铺主行，"自定义…"是预设列表最后一项（带日历图标），选择后展开更多筛选区。
- 更多筛选区展开状态不入 URL，组件内 state 即可；但当 categoryId/自定义日期已激活时，**首次进入自动展开**（沿用现有 `dateFilterExpanded` 思路）。
- 响应式：`<lg` 时主行折两行（搜索独占一行，其余均分）；摘要 Tag `flex-wrap`。

### 4.6 ASCII 全尺寸线框（桌面 1440px）

```
 Star 仓库列表                                                          ▦ ▤
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 🔍 搜索仓库名、描述、作者…        │🕐 不限 ▾│⍝ 语言 ▾│⇅ Star 最多 ▾│⚙ 更多筛选 │  ← 56px
│ 当前筛选： [关键词: react ×] [语言: TypeScript ×] [时间: 30天内 ×] [分类: AI(12) ×] 清除全部 │  ← 条件出现 32px
└──────────────────────────────────────────────────────────────────────────────────┘
 已选 3 项   [ ⧉ 批量克隆 (3) ] [ ⬇ 批量下载 (3) ]              [导出MD] [导出链接]      ← 条件出现 40px
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│ 仓库卡片…   │ │            │ │            │ │            │   ← 瀑布流提前 ~120px 进入首屏
```

## 五、备选方案对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 主行+更多筛选（推荐）** | 高频控件主行，低频进展开区 | 默认高度最低、高频一步可达、改动集中在 StarList 目录内 | 排序合并需做一次值映射 | ✅ 推荐 |
| B. 左侧筛选栏 | 筛选全部移到左边栏（类 GitHub 搜索页） | 筛选空间大、可长期展开 | 布局伤筋动骨；挤压瀑布流宽度；与现有 Tabs/侧边菜单冲突 | ❌ 过度设计 |
| C. 查询构建器 | 每个条件一个"字段+操作符+值" chip | 表达能力最强 | 学习成本高，对本场景（字段固定 5 个）杀鸡用牛刀 | ❌ 不推荐 |
