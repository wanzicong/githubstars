# 我的仓库（My Repos）功能设计文档

- **日期**：2026-08-02
- **分支**：`feature/my-repos`
- **状态**：已确认（用户授权全程自主决策）

## 1. 需求背景

平台当前只管理用户 **Star 过的** GitHub 仓库（`github_repo` 表）。用户希望把自己在 GitHub 上 **创建的仓库**（owned repos，含 public/private、含 fork 源标记）也接入平台，复用现有的同步、翻译、筛选等基础能力。

## 2. 核心设计决策（自主决策记录）

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 数据模型 | **新建 `my_repo` 表**，不给 `github_repo` 加 `source` 字段 | 加 source 字段需改约 20 处既有 SQL（clone/download/learn/category/stats），破坏面大；独立表零破坏、风险低，且字段有差异（owned 无 starredAt，多 isPrivate） |
| 2 | 数据来源 | `GET /user/repos`（type=owner, per_page=100, 翻页，sort=updated） | 覆盖 public + private；starred 接口的组织维度对 owned 无意义 |
| 3 | 增量/全量 | **UPSERT 增量，不做删除同步**（仓库改名/删除只在 GitHub 侧发生，本地保留快照） | 删除已删仓库会连带丢失其翻译成果；且 `onDelete: Cascade` 会把分类绑定一起删掉 |
| 4 | README 原文 | **同步后后台拉取**（复用 `fetchReadmeFromGitHub`，并发 5） | 与 Star 同步的 `fetchMissingReadmes` 模式一致，同步主流程不被拖慢 |
| 5 | 分类管理 | **复用现有 category 树**，新建 `my_repo_category_link` 关联表 | 分类树是通用维度；若给 `category_repo_link` 加 type 字段会让所有现有查询都要补条件 |
| 6 | 翻译中文化 | **复用现有 translate/agent 流水线**：新增 `/api/my-repos/pending-localization` + `/api/my-repos/localization` 两个兼容端点，对接 `githubstars-agent` 的 `localization-run/batch` | 现有流水线（findPending → AI 翻译 → updateTranslations 回写）完全可复用，只需按表路由 |
| 7 | 克隆/下载 | **复用 clone/download 任务体系**，任务 item 的 repoId 引用 my_repo | 任务表结构通用；批量克隆自己的项目是核心诉求之一 |
| 8 | 学习清单 | 不接入（学习清单语义是"学别人的项目"） | YAGNI |
| 9 | 统计 | **统计页加"My Repos 概览"区块**（总数/语言分布/Star 总数），不混入 Star 仓库统计 | 两类数据语义不同，分开统计更清晰 |
| 10 | UI 呈现 | 侧边栏新增分组「我的仓库」（orderNo: 2），两个页面：列表 `/my-repos`、详情 `/my-repos/:id`；复用 `RepoDetailView` 渲染详情 | 布局与 Star 列表一致，降低学习成本 |
| 11 | 同步入口 | 我的仓库列表页内「同步」按钮 + `/api/my-repos/sync` 端点，sync_log 表记录（syncType='我的仓库同步'） | 复用 SyncLog 记录体系，同步状态可观测 |
| 12 | SQLite 桌面端 | **同步修改 `schema.sqlite.prisma`**（P0 约束：双 schema 必须同步） | 第十次复盘约束 |

## 3. 数据模型

### 3.1 `my_repo` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BigInt PK | 自增主键（SQLite 版为 Int） |
| repo_name | VarChar(255) | 仓库名 |
| full_name | VarChar(500) UNIQUE | owner/repo |
| description / description_cn | Text | 描述原文 / 中文翻译 |
| readme_original / readme_cn | LongText | README 原文 / 中文翻译 |
| readme_fetched | TinyInt | 是否已拉取过 README |
| language | VarChar(100) | 主语言 |
| html_url / homepage | VarChar(1000) | 地址 |
| stars_count / forks_count / watchers_count / open_issues_count | Int | 指标 |
| topics | Text (JSON) | 主题标签 |
| license_name | VarChar(255) | 许可证 |
| is_fork / is_archived | TinyInt | fork 源标记 / 归档标记 |
| **is_private** | TinyInt | 私有仓库标记（本表特有） |
| repo_size / default_branch / visibility | Int / VarChar | 复用既有字段 |
| repo_created_at / repo_updated_at / repo_pushed_at | DateTime | GitHub 侧时间 |
| created_at / updated_at | DateTime | 本地时间 |

索引：`language`、`stars_count`、`repo_updated_at`、`is_private`。

### 3.2 `my_repo_category_link` 表

与 `category_repo_link` 同构：`id / category_id / my_repo_id / created_at`，`@@unique([categoryId, myRepoId])`，两端 `onDelete: Cascade` 关联 `Category` 与 `MyRepo`。

### 3.3 迁移

新增 migration `20260802000000_add_my_repos`（MySQL 执行 `prisma migrate deploy`；SQLite 由桌面端启动时 `db push` 对齐，与现有 Learn 表做法一致）。

## 4. 后端设计（NestJS）

### 4.1 新模块 `packages/backend/src/my-repos/`

```
my-repos/
├── my-repos.module.ts            # 注册 Controller/Service
├── my-repos.controller.ts        # HTTP 端点（ZodValidationPipe 全覆盖）
├── my-repo.service.ts            # 列表/详情/筛选/翻译状态增强（仿 GithubRepoService）
└── my-repo-sync.service.ts       # 同步逻辑（仿 SyncService，含同步锁）
```

### 4.2 GitHub API 扩展（`github-api.service.ts` 新增方法）

`fetchAllOwnedRepos(): Promise<MappedRepoData[]>`：
- 端点 `/user/repos?type=owner&per_page=100&page=N&sort=updated`
- 复用 `buildGithubHeaders` / `parseLinkHeader` / `sleep` / 去重逻辑
- 返回结构复用 `MappedRepoData`（`starredAt` 恒为 null）

### 4.3 HTTP 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/my-repos/sync` | 触发同步（同步锁防并发，返回任务受理状态） |
| GET | `/api/my-repos/sync-status` | 同步状态/上次时间/总数 |
| POST | `/api/my-repos/list` | 分页列表（keyword/language/sortBy/sortOrder/categoryId/isPrivate/dateField） |
| POST | `/api/my-repos/detail` | 按 id 查详情（含分类、翻译状态） |
| POST | `/api/my-repos/ids` | 按筛选取全部 id（跨页全选用） |
| POST | `/api/my-repos/by-ids` | 批量取详情 |
| POST | `/api/my-repos/categories/bind` | 绑定分类（批量） |
| POST | `/api/my-repos/categories/unbind` | 解绑分类 |
| GET | `/api/my-repos/pending-localization` | 待翻译记录（description+readme 双分支，与 stars 版同构） |
| POST | `/api/my-repos/localization` | 回写译文（descriptionCn/readmeCn） |
| GET | `/api/my-repos/stats` | 概览统计（总数/语言分布/总 Star） |

所有端点：Zod schema 校验、数字范围校验、字符串 trim、空值检查（P1 输入校验全覆盖）。

### 4.4 同步流程（`MyRepoSyncService`）

```
触发同步 → 同步锁检查 → 创建 SyncLog(syncType='我的仓库同步')
  → fetchAllOwnedRepos() 全量拉取
  → upsert my_repo（fullName 唯一键）
  → 更新 SyncLog(成功/失败)
  → 后台并发拉取缺失 README（并发 5，复用 fetchReadmeFromGitHub）
```

### 4.5 克隆/下载接入

- `clone` / `download` 创建任务时接受 `repoSource: 'star' | 'my'`（默认 'star' 保持兼容）
- 任务 item 增加可空 `my_repo_id` 外键（MySQL + SQLite 双 schema 同步）
- 校验：repoIds 必须在对应源表中存在（参照 category.service.ts 的先查后验模式）

## 6. 错误处理

- GitHub Token 未配置/失效：同步返回明确错误文案（引导去系统配置）
- API 限流：同步记录失败日志（SyncLog status='失败'），前端 Toast 提示稍后重试
- 翻译回写：单条失败不阻塞整批（沿用现有 updateTranslations 模式）
- 私有仓库 README 拉取失败：标记 readme_fetched=true 避免重复请求（与 stars 版一致）

- **业务逻辑（浏览器 MCP）**：同步 → 列表展示 → 筛选 → 详情 → 翻译一条 → 统计区块

## 8. 影响范围预评估

- 数据库：新增 2 表 + clone/download item 表各加 1 可空列（**中风险**：有 schema 变更，均为新增无破坏）
- API：全部为新增端点，既有端点仅 clone/download 增加可选参数（向后兼容）
- 前端：新增页面与菜单，既有页面仅 Stats 页增加区块
- 配置：无新增环境变量（复用 github.username / github.token）

## 9. 构建顺序

1. Prisma 双 schema + migrate + generate
2. 后端：MappedRepoData 复用确认 → fetchAllOwnedRepos → MyRepoSyncService → MyRepoService → Controller → 模块注册
3. 后端单测
4. 前端：api 层 → 类型 → 列表页 → 详情页 → 菜单/路由 → Stats 区块
5. 验证链（lint/build/test）→ 重启服务 → curl → 浏览器实测
