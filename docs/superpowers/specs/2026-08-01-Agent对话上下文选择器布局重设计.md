# Agent 对话上下文选择器布局重设计

- **日期**：2026-08-01
- **状态**：设计已获用户批准
- **涉及范围**：前端 `AgentChat` 页的上下文选择器（仓库/分类选择）

## 背景与问题

当前实现位于 [ContextPicker.tsx](../../packages/frontend/src/pages/AgentChat/ContextPicker.tsx)，存在以下布局与对齐问题：

1. **已选上下文独占一行**：「＋ 上下文」按钮和已选 Tag 平铺在输入框上方一整行的 flex 容器中，即使未选任何上下文也占用一整行垂直空间，把输入框顶低。
2. **Tag 平铺无约束**：选中多个上下文后 Tag 无限换行向下堆叠，输入区域被越推越大，无折叠/溢出处理。
3. **弹层内列表对齐粗糙**：仓库列表使用 Ant Design `List.Item`，图标靠 `marginRight: 6` 贴文字，无固定列宽，各行文字左边缘实际未对齐（用户反馈"看起来是右对齐，不是左对齐"）；选中态仅靠背景色区分，无勾选标记；超长仓库名截断后无 Tooltip 提示；行间无分隔线，视觉粘连。
4. **按钮样式单薄**：`type="text"` 的「＋ 上下文」按钮混在 Tag 中，视觉层级不清晰。

## 设计决策（用户已确认）

| 决策点 | 结论 |
|--------|------|
| 整体布局方向 | **A · 一体化输入框**：已选上下文收纳进输入容器内部，不占额外行 |
| 弹层列表排版 | **紧凑单行列表**：定宽复选框列 + 星标列 + 名称列 + star 数列 |
| star 数列 | 保留（48px 定宽右对齐） |
| 弹层"已选 n 项一键清空"行 | 保留（仅已有选中项时显示） |

## 第 1 节：整体布局（一体化输入框）

输入区从"上下两行（上下文行 + 输入行）"改为**单个圆角容器**，内部三层：

```
┌─────────────────────────────────────────────────┐
│ [⭐ react ✕] [⭐ vue ✕] [⑂ 前端框架 ✕] [+2]      │  ← 已选 chip 区（仅选中时渲染）
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │  ← 虚线分隔（仅有 chip 时显示）
│ 输入你想查询的 GitHub 仓库或问题…                  │  ← TextArea（无边框，融入容器）
│                                       [＋] [➤]  │  ← 右下：上下文按钮 + 圆形发送钮
└─────────────────────────────────────────────────┘
```

- **已选 chip 区**：最多完整显示 3 个 chip，超出折叠为灰色 `+N` 文字，点击 `+N` 打开弹层管理全部已选项。chip 高 22px、灰底圆角、字号 11-12px、超长省略号、各自带 ✕ 删除。
- **「＋」按钮**：图标按钮（`PlusOutlined`），放输入框右下角、发送钮左侧，Tooltip「添加上下文」。
- **发送钮**：改为 28px 圆形图标按钮（`SendOutlined`），与「＋」同排右对齐；`loading` 时变为红色 Stop 圆形钮。
- **无上下文时**：chip 区整体不渲染，容器内只剩输入框 + 右下按钮。
- **底部提示行**（`Enter 发送 · Shift+Enter 换行…`）保留在容器下方不变。
- **移动端**（isMobile）：布局不变，chip 自动换行。

## 第 2 节：弹层（从「＋」向上弹出）

- **位置**：`placement: topRight`，与「＋」按钮右对齐向上弹出；宽 360px。
- **结构**：顶部 Tabs（仓库 / 分类，保持两个 Tab 不变），Tab 内容区最大高 320px 内部滚动。
- **仓库 Tab**：搜索框吸顶（下方 8px 间距）→ 紧凑单行列表 → 空态 `Empty` 居中、加载态 `Spin` 居中。
- **分类 Tab**：保持 `Tree checkable defaultExpandAll`，仅统一子级缩进 24px、计数 `（12）` 用 `colorTextTertiary` 弱化。
- **已选行**：弹层顶部（Tabs 之上）显示「已选 n 项」+ 「清空」文字按钮，仅在已有选中项时渲染。
- **交互**：点击外部 / Esc 关闭；勾选即时生效无确认按钮。

## 第 3 节：紧凑单行列表（对齐修复核心）

每行固定四列网格，替代现有 `List.Item`：

```
[☑/☐ 16px] [⭐ 16px] [仓库名 flex:1 省略号] [star数 右对齐 48px]
```

- **复选框列**：16px 定宽居中。未选中 = 灰框，选中 = 主题色勾选。
- **星标列**：16px 定宽居中，金色 `StarOutlined`。
- **名称列**：`flex: 1; min-width: 0`，fullName 超长 `ellipsis` 截断，悬停 `Tooltip` 显示完整名。
- **star 数列**：48px 定宽右对齐，`colorTextTertiary` 11px，格式 `234k / 48.2k / 999`（优先复用项目已有数字格式化工具，没有则内联 k 转换）。
- **行样式**：高 32px、`padding: 0 10px`、行间 1px 细分隔线（`colorBorderSecondary`）、悬停 `colorFillTertiary` 背景、选中行 `colorPrimaryBg` 背景、整行可点击。
- **对齐保证**：前两列定宽 + `flex-shrink: 0`，所有行名称左边缘严格在同一垂直线上。

## 第 4 节：实现与影响范围

- **改动文件**：
  - 重写 [ContextPicker.tsx](../../packages/frontend/src/pages/AgentChat/ContextPicker.tsx)（约 230 行 → 预计 300 行内；若超 300 行，拆出 `RepoRow` 子组件到同目录单独文件，注意禁止同名异缀文件）。
  - [AgentChat/index.tsx](../../packages/frontend/src/pages/AgentChat/index.tsx)（约 1729 行处）：把 `ContextPicker` 从输入框上方挪进输入容器内部，删除原独立发送按钮（发送钮并入输入区），整合 TextArea + 「＋」+ 圆形发送钮到同一容器。
- **组件接口不变**：`value: ChatContextItem[]` + `onChange` 保持不变，AgentChat 页数据流、发送逻辑、会话逻辑零改动。
- **明确不做**：不改后端接口、不改 `ChatContextItem` 结构、不改分类勾选联动逻辑、不做虚拟滚动（20 条/页够用）。
- **风险等级**：低 —— 纯前端单组件重构，无 API/DB 变更。

## 错误处理与边界

- 仓库搜索失败：列表显示空态「无匹配仓库」，不阻断分类 Tab。
- 分类树加载失败：分类 Tab 显示「暂无分类」，不阻断仓库 Tab。
- 超长仓库名（>40 字符）：省略号 + Tooltip 兜底。
- 已选 0 项：chip 区与弹层「已选行」均不渲染。
- 已选 >3 项：chip 区折叠为 3 个 + `+N`。

## 测试与验证

1. `npm run lint`（前端包目录下）零 error、`grep sonarjs` 零输出。
2. `npm run build`（前端包目录下，`tsc -b && vite build`）零 error。
3. 浏览器实测（Playwright MCP 或手动）三种状态：
   - 无上下文：输入容器只有输入框 + 右下按钮，无多余行。
   - 选 3 个以内：chip 全部展示，可单独删除。
   - 选 5 个以上：chip 折叠为 3 个 + `+N`，点击 `+N` 打开弹层。
4. 弹层交互：搜索、勾选/取消、已选行清空、分类树勾选，均即时生效。
5. 发送/停止按钮在 loading 与非 loading 态下切换正常，发送逻辑与现状一致。

## 前端四维审查要点（实现时逐条过）

- **交互友好**：「＋」/发送/停止按钮有 hover 与 disabled 态；chip 删除即时生效。
- **用户体验**：弹层加载/空态/错误三态覆盖；搜索防抖保持 300ms。
- **前端性能**：chip 与列表行的 key 用 `type-id` 复合键；搜索防抖定时器在 effect cleanup 中清除。
- **视觉安全**：名称列 `min-width: 0` + ellipsis + Tooltip；弹层 320px 内部滚动不撑破；窄屏（<1024px）容器宽度 100% 自适应。
